# 移动端照片编辑器吸顶头部设计

## 目标

在宽度不超过 720px 的移动端照片编辑页中，用户向下滚动时，返回按钮、页面标题和删除按钮所在的头部保持在视口顶部，方便用户随时返回照片库或执行删除操作。桌面端编辑器布局保持不变。

## 交互

- 编辑页刚打开时，头部仍位于页面原有位置，不产生额外浮层或跳动。
- 当编辑器内容向上滚动时，头部使用 CSS `position: sticky` 自动吸附到滚动容器顶部。
- 头部吸顶后，照片、表单、保存反馈和保存按钮继续在其下方正常滚动。
- 返回与删除按钮保留当前事件、可访问名称和至少 44px 的触控区域。
- 不增加滚动监听器、观察器或新的 Vue 状态。

## 视觉与安全区

- 头部仅在移动端成为 sticky；桌面端现有 sticky 编辑侧栏不变。
- sticky 头部覆盖编辑器左右内边距，使其视觉上形成完整的顶部工具栏。
- 顶部内边距包含 `env(safe-area-inset-top, 0px)`，兼容 iPhone 刘海和独立 Web App 安全区。
- 使用不透明的后台纸张色、底部分隔线和轻微阴影，避免下方照片或文字穿透。
- 使用明确的 `z-index`，确保头部高于编辑器内容，但低于删除确认和重新登录模态框。

## 实现范围

- 修改 `src/styles/admin.css` 的移动端编辑器与头部规则。
- 更新 `src/admin/AdminApp.test.ts` 中的移动端布局合同，验证 sticky、顶部位置、安全区、背景和层级。
- 除非测试发现结构限制，不修改 `PhotoEditor.vue` 或业务状态管理。

## 验收标准

1. iPhone 14 尺寸下进入照片编辑页，向下滚动后头部保持可见。
2. 头部不会遮住照片首屏内容，也不会产生横向溢出。
3. 返回、删除、编辑、保存及日期输入行为无回归。
4. 桌面照片库双栏布局无变化。
5. `prefers-reduced-motion` 无额外动画问题，因为本功能不引入动画。

## 测试

- 实现最小 CSS 后运行相关单测、类型检查与 lint。
