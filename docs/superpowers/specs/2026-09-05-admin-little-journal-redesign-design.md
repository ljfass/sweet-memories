# 管理员相册“小小成长志”界面设计

日期：2026-09-05

状态：视觉方向已确认，待书面规格复核

## 1. 背景

当前管理员界面已经具备登录、照片上传、上传队列、刷新、照片数量、编辑、保存反馈、永久删除、会话过期恢复和移动端全屏编辑等完整能力。现有界面功能清晰，但整体更接近通用管理后台，照片与家庭成长主题之间的情感联系较弱。

本次设计在不改变业务流程的前提下重做视觉层级。已确认的方向以 **H「小小成长志」**为主体，保留 **F「成长手账」**的照片装裱感：日期叙事负责组织内容，纸张式边框只用于照片及预览，不把整个后台装饰成仿真手账。

改造级别采用用户确认的 **B**：允许调整信息层级、页面布局和视觉语言，但不新增或改变业务能力、数据合同与操作结果。

## 2. 设计目标

- 第一眼仍然是高效、可靠的照片管理工具。
- 让照片成为页面中最强的视觉内容，装饰不得与照片争夺注意力。
- 通过日期、标题语气和克制的纸张层次体现家庭成长记录的温度。
- 保持桌面端连续编辑效率，以及移动端双列浏览和全屏编辑体验。
- 保留全部既有状态、可访问性、并发保护和失败恢复行为。
- 在 19 张及更多照片下维持可扫描、可扩展的布局。

## 3. 参考原则

- Google Photos：缩略图更大、图片间留白更少，让照片而非界面成为主角。
- Apple Photos：图库结构稳定，主操作清晰，次要控件保持克制。
- FamilyAlbum：通过日期和成长阶段帮助家庭成员回看内容。
- Day One：使用轻量排版和时间信息营造记录感，而不是依赖复杂装饰。
- Material 3 Expressive 与 Dropbox：在有限区域使用鲜明颜色和形状建立情绪与品牌辨识度。

以上只作为设计原则来源，不复刻任何产品界面或品牌元素。

## 4. 视觉系统

### 4.1 配色

采用浅色模式，不新增深色模式。

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 雾粉画布 | `#F7F4F5` | 页面背景，提供轻微温度但不呈现大面积米黄色 |
| 照片纸白 | `#FFFDFD` | 照片装裱、编辑器和对话框表面 |
| 莓果主色 | `#B84061` | 上传、选中、品牌标记和主操作 |
| 莓果按压色 | `#8F2F4A` | 主按钮按压或下沿强调 |
| 湖蓝辅助色 | `#39767A` | 数量、次级品牌信息、键盘焦点 |
| 暖阳提示色 | `#EFA95A` | 日期分组短线和非错误提醒 |
| 成功色 | `#28674D` | 保存和完成状态，必须与图标或文字共同使用 |
| 主文字 | `#2D292C` | 标题和正文 |
| 次文字 | `#70676C` | 辅助说明和时间 |
| 分隔线 | `#DFD6DA` | 边框和分隔线 |

错误、警告、禁用和成功状态继续使用语义色，不用莓果主色冒充错误色。

### 4.2 字体

- 页面命令、表单、按钮和状态信息继续使用 `PingFang SC`、`Microsoft YaHei` 和系统无衬线字体。
- 品牌名称、照片标题、日期分组标题可使用 `Songti SC` 或系统衬线回退，形成轻量日记感。
- 正文不使用小于 `14px` 的生产字号；按钮和移动端输入保持可读。
- 字间距保持默认值 `0`，不使用装饰性紧缩字距。

### 4.3 形状与阴影

- 功能控件圆角为 `6px` 至 `8px`，不使用大面积胶囊形按钮。
- 状态标签可使用胶囊形，但必须是简短状态而非普通命令。
- 照片使用 `6px` 内边距、细边框和低强度阴影形成装裱感。
- 编辑器使用白色表面与淡湖蓝偏移阴影，表达“记录页”但保持工具边界。
- 页面区块不套装饰卡片；卡片只用于照片、编辑器、对话框和上传队列项等真实对象。
- 不使用渐变、光斑、装饰性圆球、纹理背景或卡通贴纸。

### 4.4 图标

- 继续使用现有 Lucide 图标。
- 上传、刷新、删除、返回和成功状态维持统一描边粗细。
- 不使用 Emoji 充当结构性图标。
- 仅图标按钮继续提供 `aria-label` 和 `title`。

## 5. 桌面端信息架构

### 5.1 顶部工具栏

- 左侧保留“甜蜜回忆 / 相册管理”品牌与页面标题。
- 品牌标记改为莓果红方形“忆”字标识，并使用轻微粉色偏移阴影。
- 右侧保留管理员用户名和“退出登录”。
- 工具栏仍是全宽边界，不改成悬浮卡片。

### 5.2 相册标题与操作

- 页面主标题由“照片库”调整为“成长相册”。
- 当前数量继续紧邻标题显示为“共 N 张”，使用湖蓝辅助色和等宽数字特性。
- 上传和刷新位于标题行右侧；上传是唯一主按钮，刷新保持次按钮。
- 上传队列存在时继续出现在操作区下方，不改变并发、暂停、重试或两阶段进度语义。

### 5.3 日期分组

- 照片在客户端严格按现有 API 返回顺序展示，不改变服务端数据或公开相册排序。
- 渲染时只在相邻照片的 `capturedDate` 年份发生变化处建立新分段，例如“2026 年 · 成长片段”；不另外排序、聚合或移动照片。
- 若异常数据使同一年份在后续再次出现，则新建同名年份分段，以保留原始顺序。
- 没有拍摄日期的照片进入“待补充日期”分组，仍可正常选择和编辑。
- 分组标题使用衬线字体、暖阳色短线和克制字号，不加入折叠、筛选或导航功能。

### 5.4 照片装裱

- 桌面端维持响应式网格，照片最小列宽仍不低于 `180px`。
- 每张照片由纸白表面、细边框、`6px` 内边距和轻阴影构成。
- 图片本身保持方形裁切和稳定尺寸，不发生布局偏移。
- 标题位于照片下方，使用衬线字体；拍摄日期作为次级文字显示在标题下方。
- 选中状态使用莓果边框、外圈和带对勾的选择标记，不只依赖颜色。
- 不随机旋转照片。装裱感来自边框与阴影，确保大量照片时网格稳定、整齐。

### 5.5 右侧编辑器

- 继续使用 `320px` 左右的 sticky 编辑器，不改变选择照片后的工作流。
- 标题区显示辅助文字“照片信息”和主标题“记录这张照片”。
- 删除按钮仍位于右上角，使用语义危险色，与保存操作分离。
- 编辑预览也使用纸白装裱，但不嵌套额外装饰卡片。
- 字段顺序保持标题、拍摄日期、图片描述。
- 主命令保持明确的“保存修改”，避免用过度文学化文案替代关键操作。
- 保存成功继续在表单消息位置显示绿色图标和“保存成功”，不增加 Toast 或自动消失。

## 6. 移动端设计

- `720px` 以下继续使用双列照片网格。
- 装裱内边距和阴影在移动端缩小，保证图片可视面积。
- 上传与刷新继续使用底部 sticky 操作区；上传为主要宽按钮，刷新可使用带可访问名称的图标按钮。
- 点击照片继续打开现有全屏编辑器，不把桌面右栏压缩进窄屏。
- 全屏编辑器继续提供返回按钮、焦点圈、Tab 焦点约束和安全区底部内边距。
- 编辑器、删除确认和重新登录对话框继续遵循单一模态边界，背景保持 `inert` 与 `aria-hidden`。
- 输入框与触控控件的交互区域不得小于 `44px`。

## 7. 状态与反馈

### 7.1 加载、空态和错误

- 加载状态保留稳定占位，不让标题或工具栏跳动。
- 空相册显示简短说明和上传入口，不使用插画或营销式空态。
- 加载失败继续显示经过净化的固定错误文案及“重试”按钮。

### 7.2 迁移准备

- “正在准备旧照片，暂未开放上传”继续位于工具栏和照片之间。
- 使用暖阳提示色、图标或粗体标题和说明文字，不只通过背景颜色表达状态。
- 上传禁用、编辑可用和刷新可用的行为保持不变。

### 7.3 上传队列

- 上传队列使用分隔行而不是大卡片堆叠。
- 文件缩略图可使用与照片一致但更轻的纸白边框。
- 两阶段进度继续区分“正在上传”和“服务器处理中”；进度条不伪造服务端处理百分比。
- 网络错误、磁盘不足、会话暂停、显式继续和失败项重试行为完全保留。

### 7.4 保存、冲突和删除

- 保存成功使用绿色勾选图标、文字和淡绿色背景。
- 保存失败和版本冲突使用明确文案与恢复操作，不只改变颜色。
- 删除继续使用二次确认和危险色，不提供模糊的“移除”表达。
- 删除完成后的焦点恢复规则保持 next → previous → 相册标题。

## 8. 动效与交互状态

- hover、focus、pressed 和 selected 的过渡控制在 `150ms` 至 `220ms`。
- 动效只使用颜色、阴影、透明度和必要的 `transform`，不改变布局尺寸。
- 照片 hover 只增强阴影或边框，不大幅缩放照片。
- 按钮按压可通过阴影收回表达，不移动周围布局。
- `prefers-reduced-motion: reduce` 时取消非必要过渡。
- 所有状态变化在 `100ms` 内提供视觉响应；网络操作继续显示既有进行中状态。

## 9. 组件与数据边界

### 9.1 `AdminApp.vue`

- 只负责页面品牌、会话状态、主标题和模态隔离。
- 不新增业务状态或重复保存照片数量。

### 9.2 `PhotoLibrary.vue`

- 从现有照片数组派生只读年份分组。
- 渲染日期分组与装裱照片卡。
- 保持上传、刷新、选择、删除候选、焦点恢复和移动端模态逻辑。

### 9.3 `PhotoEditor.vue`

- 调整标题层级和装裱预览结构。
- 保持字段、事件、草稿、冲突、保存、删除和成功消息接口不变。

### 9.4 `UploadQueue.vue` 与对话框

- 主要通过共享设计 token 和 CSS 统一视觉。
- 不改变队列调度、请求 ID、Abort、登录代际或对话框状态机。

### 9.5 `admin.css`

- 集中定义颜色、间距、圆角、阴影和响应式规则。
- 使用语义变量减少零散色值，但不引入外部 UI 框架或 CSS-in-JS。

## 10. 错误处理与安全边界

- 本次不修改 API、认证、Cookie、CSRF、上传或数据库逻辑。
- 不把服务端错误、文件路径、请求 ID 或敏感信息呈现在新视觉元素中。
- 视觉重排不得卸载未保存编辑器草稿或上传队列。
- 重新登录出现时继续保留实际 DOM 草稿节点，成功后不自动保存或续传。
- 刷新、上传、保存和删除的现有竞态保护不得因分组渲染而失效。

## 11. 测试与验证

### 11.1 组件测试

- 日期分组：多个年份、同一年、无日期和空图库。
- 照片卡：标题、日期、稳定图片尺寸、选中状态和可访问名称。
- 编辑器：字段顺序、保存成功、冲突、删除和移动端返回行为。
- 上传队列：两阶段进度、暂停、继续、错误和文件名溢出。
- 管理页：照片数量、上传后增加、删除后减少、刷新后同步。

### 11.2 回归测试

- 草稿在刷新和重新登录期间保留。
- 旧请求不会覆盖新加载、保存、上传或删除结果。
- 上传最多同时两张，401 后不自动续传。
- 删除对话框和重新登录对话框不会叠加两个活动模态框。
- 键盘焦点、`inert`、`aria-hidden` 和 `aria-live` 行为保持通过。

### 11.3 视觉验证

- 桌面：`1440 × 900`，验证四列以上网格、sticky 编辑器、长标题和队列展开。
- 移动：`390 × 844`，验证双列装裱、底部操作区、全屏编辑器和安全区。
- 小屏：`320px` 宽，验证按钮文字、长文件名和错误文案不溢出。
- 检查高对比焦点、200% 文本缩放和 `prefers-reduced-motion`。
- 浏览器工具可用时保存桌面与移动截图；不可用时必须明确记录限制并进行人工浏览器验收。

## 14. 验收标准

- 页面整体符合已确认的 H 主体 + F 照片装裱方向。
- 桌面和移动端照片均保持内容优先、无横向滚动、无文字重叠。
- 日期分组可正确处理合法日期和缺失日期。
- 照片装裱不改变图片比例、响应式资源或点击区域。
- 上传、刷新、数量、编辑、保存反馈、冲突、删除和重新登录全部可用。
- 所有交互控件可通过键盘访问，焦点明显，状态不只依赖颜色。
- 管理端 focused tests、source-only root tests、typecheck、lint 和 frontend build 全部通过。
