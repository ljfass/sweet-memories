# 后台上传与刷新即时反馈设计

## 背景

相册管理页已经展示上传队列，并在队列项目内记录每张照片的上传状态，但批量上传全部完成时缺少跨滚动位置可见的明确反馈。用户主动刷新照片库成功后也没有即时成功提示，容易误以为按钮没有生效。

本设计参考 Sonner、Radix Toast 和 Vue Toastification 的非阻断通知模式，但不引入新的第三方依赖，继续使用项目现有 Vue 组件、颜色变量和管理端样式。

## 目标

- 批量上传全部成功后，立即显示一次全局成功提示。
- 用户主动刷新成功后，立即显示一次全局成功提示。
- 上传队列及每张照片的成功、失败、暂停记录继续保留。
- 提示在桌面端和移动端当前滚动位置都可见。
- 不影响上传并发、重登后手动续传、草稿、刷新滚动位置和照片集合竞态保护。

## 非目标

- 不替换或删除现有上传队列。
- 不把每张照片的上传成功分别弹成多条提示。
- 不为初次加载、上传后的内部数据同步或自动恢复显示“刷新成功”。
- 不改变 API、上传协议、数据库结构或照片排序规则。
- 不引入 Toast 组件库或新的运行时依赖。

## 视觉方案

采用确认的 `C1` 方案：固定在视口顶部的轻量成功提示。

- 桌面端位于右上角，保持与页面边缘和管理端顶栏的稳定间距。
- 移动端位于顶部居中，宽度受视口内边距约束，并考虑 `env(safe-area-inset-top)`。
- 提示使用现有成功绿色、白色底和轻微阴影，包含成功图标及简短文案。
- 上传成功文案为“`N 张照片上传完成`”。
- 刷新成功文案为“`刷新成功 · 共 N 张`”。
- 提示层不改变文档流，不推动照片网格或工具栏产生布局位移。
- 提示不遮挡 iPhone Chrome 底部工具栏、移动端固定保存按钮或相册悬浮操作胶囊。

## 上传反馈

### 批次边界

一次文件选择形成一个上传批次。提示按批次聚合，不按单个队列项目产生。

- 批次中的全部项目成功后显示一次“`N 张照片上传完成`”。
- 同一批次的成功提示最多显示一次，即使队列状态再次同步或组件重新渲染也不得重复提示。
- 如果批次存在失败、暂停或等待重新登录的项目，不显示“全部上传完成”；既有队列继续显示精确状态和恢复入口。
- 用户稍后重试后使该批次全部成功时，再显示一次完成提示。
- 不删除成功队列项目，用户仍可逐张核对上传结果并按现有方式清理记录。

### 与照片库同步

成功上传的照片继续按现有逻辑立即加入照片库。全局提示只表达批次完成，不参与照片数据合并，也不改变上传项目的 request ID、重试或取消逻辑。

## 刷新反馈

- 只有用户点击桌面工具栏或移动端悬浮胶囊中的刷新按钮，且当前刷新请求成功并被状态机接受后，才显示“`刷新成功 · 共 N 张`”。
- `N` 取成功合并后的当前照片集合长度，不维护单独计数。
- 初次页面加载不显示成功提示。
- 上传完成后的内部照片同步不显示刷新提示。
- 过期、被更新请求取代或未被 generation 校验接受的响应不得显示成功。
- 刷新失败继续使用现有错误反馈，不显示成功提示，也不清空现有照片或草稿。
- 刷新保持既有原地更新和滚动位置保护，不因提示出现而回到页面顶部。

## 通知状态与并发

- 使用管理端内部的轻量通知状态，不接管现有表单消息或队列消息。
- 同一时刻最多显示两条提示，满足上传完成与刷新成功接近发生时两者都即时可见。
- 新提示按发生顺序排列；先发生的提示先离开。
- 相同动作因重复状态通知产生的同文案提示需要去重，但不同真实批次可以分别提示。
- 每条提示默认显示约 3.5 秒。
- 鼠标悬停或键盘焦点进入提示时暂停倒计时，离开后继续。
- 组件卸载时清理全部计时器，避免迟到更新或测试句柄泄漏。
- 登录过期弹窗、删除确认框和移动端编辑器打开时，提示仍可被辅助技术播报，但不得抢占模态焦点或成为背景中的可交互控件。

## 动效与可访问性

- 通知容器使用 `role="status"` 和 `aria-live="polite"`，成功消息不会打断更高优先级错误播报。
- 提示出现和离开采用短距离纵向位移与透明度过渡，不使用弹跳或大幅缩放。
- `prefers-reduced-motion: reduce` 下取消位移，仅保留即时显隐或极短淡入淡出。
- 提示不会自动获取焦点，也不会改变当前输入框、照片卡片或按钮的焦点。
- 绿色不是唯一信息来源，成功图标和完整文案共同表达状态。
- 文案允许在窄屏换行，不得造成横向滚动或超出 iPhone 14 视口。

## 组件与状态边界

- 在管理端照片库范围增加一个可复用的成功通知层，位置固定于视口，不嵌套在上传队列或照片卡片中。
- `useUploadQueue` 暴露可靠的批次完成事件或等价状态，事件只在批次首次变为全部成功时产生。
- `usePhotoLibrary` 在被接受的主动刷新完成后产生刷新成功结果，并提供合并后的照片数量。
- `PhotoLibrary` 负责把上传和刷新结果转换为用户可见通知；业务 composable 不直接操作 DOM 或计时器。
- 现有上传队列继续负责进行中、暂停、失败和逐项成功状态，不因通知层引入第二份队列状态。

## 测试

- 上传队列：单张和多张批次全部成功时只产生一次完成结果；失败、暂停和 401 状态不产生成功；重试后全部成功时产生一次。
- 照片库：用户主动刷新成功产生包含最新数量的结果；初次加载、内部同步、失败和过期响应不产生成功。
- 通知层：最多同时显示两条；3.5 秒后依次消失；悬停和焦点暂停；卸载清理计时器；相同状态重复同步不重复显示。
- 组件：桌面和移动端文案正确，通知使用 `role="status"` / `aria-live="polite"`，不会抢焦点。
- CSS 合同：桌面右上、移动端顶部居中，包含安全区处理、窄屏换行和 reduced-motion 规则。
- 回归：上传并发最多两张、401 暂停与手动续传、队列记录保留、刷新不回顶、草稿、删除和移动端模态行为继续通过。

## 验收标准

1. 上传一个或多个文件全部完成后，当前滚动位置立即出现一次批次成功提示。
2. 成功提示消失后，上传队列中的成功记录仍然存在。
3. 用户主动刷新成功后立即看到最新照片数量；刷新失败绝不显示成功。
4. 上传完成与刷新成功接近发生时，两条消息均可看到且不会覆盖。
5. iPhone 14 Chrome 上提示不超出视口、不与底部浏览器工具栏或保存按钮冲突。
6. 键盘焦点、重新登录、草稿、上传恢复和照片列表滚动位置不受提示影响。
