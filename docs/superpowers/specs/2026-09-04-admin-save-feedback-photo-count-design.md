# 后台保存反馈与照片数量设计

## 目标

在现有相册管理页补充两个直接反馈：照片信息保存成功后明确提示用户，以及在照片库标题旁显示当前照片总数。改动不得影响草稿、并发写入、重新登录、上传队列或永久删除的既有行为。

## 界面

- 照片库标题显示为“照片库  共 N 张”。“共 N 张”使用较小、较弱的辅助文字，不改变标题层级。
- `N` 是当前后台照片集合 `photos.length`，包含已发布照片和迁移准备中的照片。
- 保存成功提示复用照片编辑器现有表单消息位置，显示绿色“保存成功”。
- 保存失败、版本冲突、校验失败和登录过期继续显示现有错误文案与错误颜色。
- 不新增 Toast、弹窗或定时消失逻辑。

## 状态与数据流

- 每张照片的表单消息由纯字符串扩展为结构化状态，至少包含文案和 `success` / `error` 类型；无消息时返回空状态。
- 只有 PATCH 成功且响应版本被当前照片快照接受后，才写入“保存成功”。迟到或过期的响应不得显示成功。
- 用户再次编辑该照片时清除它的成功提示。
- 用户切换照片时清除刚离开的照片的成功提示；错误状态保持既有处理规则。
- 初次加载和刷新通过服务器响应替换照片集合；上传成功立即加入集合；永久删除成功立即移出集合。因此标题数量自动反映这四类变化，不维护第二份计数状态。

## 可访问性与布局

- 编辑器消息继续使用 `aria-live="polite"`，成功和失败都能被辅助技术播报。
- 成功状态使用语义化 class 或 data attribute 控制颜色，不根据文案内容推断状态。
- 数量文字属于照片库标题的可读内容，同时使用固定的辅助样式，避免数量位数变化导致工具栏布局跳动或窄屏溢出。

## 测试

- composable：成功保存后产生 success 消息；失败、冲突和迟到响应不产生 success；再次编辑或切换照片后清除 success。
- 编辑器：success 与 error 使用不同状态标记，并保留 `aria-live`。
- 管理页：初始加载显示数量，上传后加一，删除后减一，刷新后与服务器集合一致。
- 回归：草稿、版本冲突、401 重新登录、上传队列和删除焦点行为继续通过现有测试。

## 范围外

- 不增加成功 Toast、声音、动画或自动隐藏计时器。
- 不拆分“已发布 / 待完善”数量。
- 不修改 API、数据库结构或生产数据。
