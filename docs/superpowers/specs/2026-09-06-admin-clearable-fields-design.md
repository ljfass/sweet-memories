# 管理后台输入字段清空功能设计

日期：2026-09-06

状态：已确认，可进入实施计划

## 1. 目标

为管理后台所有可见、可手动编辑的输入字段提供一致的单字段清空操作。用户可以通过输入框右侧的清空图标删除当前字段全部内容，并立即继续输入。改动不得影响现有登录、重新登录、照片草稿、保存冲突、删除、上传或会话恢复行为。

## 2. 覆盖范围

清空功能覆盖以下字段：

- 管理员登录：用户名、密码。
- 会话重新认证：用户名、密码。
- 照片编辑：标题、拍摄日期、图片描述。

隐藏的照片文件选择器不纳入本功能。公开相册当前没有可编辑输入字段，不需要修改。

## 3. 交互规则

- 字段为空时不显示清空按钮，避免无效操作和视觉噪声。
- 字段有内容且可编辑时，在字段右侧显示 `X` 图标按钮。
- 点击按钮只清空当前字段，不影响同一表单中的其他字段。
- 清空操作使用 `button type="button"`，不得触发表单提交。
- 清空后焦点返回原字段，用户可以立即重新输入。
- 字段禁用或表单正在提交、保存时，清空按钮同步禁用。
- 密码字段保留现有显示或隐藏密码按钮；清空按钮是独立操作，两个图标不得重叠。
- 拍摄日期通过现有草稿状态清空为字符串空值，不依赖浏览器私有的日期清空控件。
- 图片描述的清空按钮位于文本域右上角，并为正文保留足够内边距。

## 4. 组件设计

新增一个轻量的共享清空按钮组件，仅负责图标、可访问名称、禁用状态和点击事件。它不持有字段值，也不封装标签、输入框或验证规则。

各表单继续拥有自己的状态：

- `AdminLogin.vue` 清空本地用户名或密码状态。
- `ReauthDialog.vue` 清空重新认证表单的本地状态。
- `PhotoEditor.vue` 通过现有 `update-draft` 事件把对应字段更新为空字符串。

字段容器增加统一的定位 class，为单图标和密码双图标提供稳定的右侧空间。样式继续集中在现有管理端样式体系中，不引入新的 UI 框架。

## 5. 状态与数据流

- 登录和重新认证字段清空后，继续沿用现有输入变更、校验和错误提示规则。
- 照片字段清空属于普通草稿修改，会将照片标记为有未保存更改。
- 标题虽然可以在界面中暂时清空，但提交时仍由现有验证规则阻止空标题保存。
- 日期和描述清空后按现有保存合同提交；描述最终映射为 `null` 的既有行为保持不变。
- 清空按钮不发起 HTTP 请求，不自动保存，也不重置照片版本或冲突状态。

## 6. 可访问性

- 使用现有 Lucide `X` 图标，不手绘 SVG，不用文字胶囊按钮。
- 每个按钮提供与字段对应的 `aria-label` 和 `title`，例如“清空密码”“清空拍摄日期”。
- 按钮保持键盘可聚焦，并使用现有管理后台焦点样式。
- 清空后以编程方式恢复字段焦点；不得把焦点留在已隐藏的清空按钮上。
- 按钮触控区域不小于 40px，并与现有移动端表单布局兼容。
- 图标本身标记为 `aria-hidden="true"`，避免重复播报。

## 7. 错误处理

- 清空是同步本地操作，不新增网络错误状态。
- 如果目标字段引用在操作前已卸载，清空状态仍可完成，但不尝试聚焦不存在的元素。
- 登录失败、重新认证失败、保存失败和版本冲突继续使用现有净化后的消息，不根据清空按钮状态生成新错误文案。

## 8. 测试

- 共享按钮：有明确可访问名称、使用普通按钮类型、禁用时不触发清空。
- 登录页：用户名和密码有值时显示清空按钮；逐字段清空；清空后恢复焦点；密码显示切换不受影响。
- 重新认证：用户名和密码逐字段清空；焦点约束仍然有效；提交中按钮禁用。
- 照片编辑：标题、日期和描述逐字段清空并发出正确草稿；空字段隐藏按钮；保存中禁用。
- 回归：登录提交、密码显示切换、重新认证焦点陷阱、草稿保留、标题必填验证、保存成功和冲突处理继续通过现有测试。
- 运行管理端 focused tests、类型检查、lint、前端构建及源代码测试集。

## 9. 范围外

- 不提供整张表单一次性全部清空。
- 不清空文件选择器或上传队列。
- 不增加撤销、确认弹窗、自动保存或 Toast。
- 不修改 API、数据库、认证 Cookie、CSRF 或生产数据。
- 不将所有表单字段重构为新的通用输入组件。
