# 管理员图片上传功能设计

日期：2026-08-31

状态：已通过对话分节评审和书面规格复核

## 1. 背景

当前项目是由 Vue 3 和 Vite 构建的静态成长相册。五张照片及其响应式资源在构建期写入前端代码，Nginx 直接提供 `dist` 内容，GitHub Actions 通过 Tag 自动发布静态文件。

本功能在不购买 OSS、云数据库或第二台服务器的前提下，为同一台阿里云服务器增加仅管理员可用的图片上传和管理能力。公开访客仍然只浏览相册；管理员通过 HTTPS 登录 `/admin` 后上传、编辑和删除照片。

## 2. 目标

- 管理员可从手机或电脑一次上传最多 10 张照片。
- 上传成功的照片自动发布到公开成长相册。
- 管理员可修改标题、拍摄日期和可选图片描述。
- 公开相册按拍摄日期从早到晚排列。
- 服务端校验、净化并生成响应式图片，不公开原文件名或 EXIF/GPS。
- 图片、SQLite 数据库和备份独立于程序发布目录，Tag 发布不得覆盖它们。
- 在当前 2 核、2GB 内存、40GB 系统盘的服务器上保持有界资源使用。
- 现有五张照片无感迁移，现有视频、音频和公开相册视觉效果保持可用。
- 登录、上传、编辑、删除、部署、备份和恢复均有可复现的验证方式。

## 3. 非目标

- 不支持访客注册、访客上传或多管理员权限体系。
- 不支持视频或音频上传；现有视频和音频继续作为静态资源发布。
- 不提供草稿、审核流、回收站或软删除。
- 不提供标签、地点、搜索、长篇故事或社交互动。
- 不提供照片替换；需要更换时删除旧照片并重新上传。
- 不自动把备份上传到第三方云存储。
- 不以隐藏 `/admin` 地址代替身份认证。

## 4. 方案选择

### 4.1 已采用

在当前服务器上运行独立 Node.js API，使用 SQLite 保存结构化数据，使用服务器持久化目录保存图片。Nginx 继续作为唯一公网入口和 TLS 终止点。

该方案没有新增云产品费用，能够保留现有 Vue 前端和 Nginx，并允许程序与用户数据分别发布和备份。

### 4.2 未采用

- 不把上传图片放入 `/var/www/huangjianfen.cn/releases/<SHA>`。这些目录由自动部署创建和清理，不能承载用户数据。
- 不直接由浏览器写服务器文件系统。
- 不在首期引入 OSS 和云数据库；当前容量和访问规模不需要它们。
- 不把完整网站改成由 Node.js 提供静态文件；Nginx 继续高效提供前端和媒体资源。

## 5. 系统架构

```text
Internet
   |
   v
Nginx :443
   |-- /             -> 当前 Vue 前端
   |-- /admin        -> 同一个 Vue 前端的管理员路由
   |-- /api/*        -> 127.0.0.1 上的 Node.js API
   `-- /media/*      -> 只读提供持久化图片

Node.js API
   |-- 管理员认证和服务端会话
   |-- 公开照片读取接口
   |-- 管理员上传、编辑和删除接口
   |-- 单并发图片处理器
   `-- SQLite 数据访问
```

API 使用 TypeScript 和 Fastify，作为 `systemd` 服务运行，只监听回环地址，不在阿里云安全组开放新端口。图片处理使用 Sharp。具体依赖版本在实施计划中固定并提交锁文件。

## 6. 服务器目录和权限

持久化数据根目录为：

```text
/var/lib/sweet-memories/
|-- database/
|   `-- app.db
|-- media/
|   `-- <photo-id>/
|-- staging/
`-- backups/
```

后端程序使用独立版本目录：

```text
/opt/sweet-memories-api/
|-- releases/<commit-sha>/
`-- current -> releases/<commit-sha>/
```

约束如下：

- API 服务账号可以读写 `database`、`media`、`staging` 和 `backups`。
- Nginx 只能读取 `media`，不能写数据库和 staging。
- SSH 部署账号可以创建程序版本并切换 `current`，不能读取管理员明文密码，因为系统中不存在明文密码文件。
- 前端发布继续使用现有 `/var/www/huangjianfen.cn/releases` 和 `html` 软链接。
- 数据目录不位于任何前端或后端 release 目录内。

## 7. 数据模型

### 7.1 管理员

`admins` 至少保存：

- `id`
- 唯一用户名
- Argon2id 密码哈希
- 创建和更新时间

首次部署后由服务器交互式命令创建管理员。命令隐藏输入密码、要求输入两次并校验一致，密码至少 12 位。重置密码也只能通过服务器交互式命令执行。源代码、GitHub Secrets、环境文件、日志和 SQLite 中均不保存明文密码。

### 7.2 会话

`sessions` 至少保存：

- 会话 ID
- 随机会话令牌的哈希，不保存令牌原文
- 管理员 ID
- CSRF 校验材料
- 创建时间、最后活动时间和绝对过期时间

随机令牌至少包含 256 位安全随机性。浏览器只通过安全 Cookie 持有原始令牌。

### 7.3 照片

`photos` 至少保存：

- 服务端生成的不可预测照片 ID
- 标题
- 可空图片描述
- 拍摄日期，使用 `YYYY-MM-DD` 保存照片所在地的日历日期，不保存时区或时分秒
- 创建和更新时间
- 发布状态：旧照片迁移准备阶段为 `migration_pending`，正常上传成功后为 `published`
- 主图尺寸及各响应式资源的尺寸、格式和相对媒体路径
- 用于保留拍立得视觉效果的稳定旋转和偏移参数
- 客户端上传请求 ID，用于幂等去重

公开显示文本使用图片描述；图片描述为空时回退为标题。公开排序为 `captured_date ASC, created_at ASC, id ASC`。公开接口只返回 `published` 记录，`migration_pending` 记录不会提前出现在公开相册。

系统设置保存 `uploads_enabled` 开关。首次迁移准备阶段默认为关闭；只有公开相册切换到 API 并通过生产健康检查后才开启。开关关闭时，管理端仍可查看和编辑迁移记录，但上传接口必须拒绝新照片。

数据库启用外键和适合单机服务的 SQLite WAL 模式。所有架构迁移必须有明确版本，自动部署只执行向后兼容的扩展型迁移。

## 8. API 边界

### 8.1 公开接口

- `GET /api/health`：返回最少量健康状态，不泄露文件路径、依赖版本或运行环境。
- `GET /api/photos`：只返回已发布照片及公开字段，按拍摄日期排序。

公开响应不包含原文件名、EXIF、GPS、管理员信息、数据库键值、绝对路径或 staging 状态。

### 8.2 管理接口

- 创建、检查和删除管理员会话。
- 获取管理员照片库。
- 一次请求上传一张照片。
- 修改照片标题、拍摄日期和图片描述。
- 永久删除一张照片。

所有修改接口同时要求有效会话、合法 Origin 和 CSRF Token。错误使用稳定的机器可读错误码及简短中文信息；响应和日志都不得回显密码、Cookie、Token、原文件名或照片二进制内容。

## 9. 登录和会话安全

管理员访问 `https://huangjianfen.cn/admin` 时，未登录状态显示用户名和密码表单。登录流程为：

1. 浏览器通过 HTTPS 提交用户名和密码。
2. API 使用 Argon2id 验证密码。
3. API 生成随机会话令牌，仅将令牌哈希写入 SQLite。
4. 浏览器收到带 `HttpOnly`、`Secure`、`SameSite=Strict`、`Path=/` 且不设置 Domain 的 `__Host-` Cookie。
5. 后续管理员请求由 API 校验 Cookie、会话时限、Origin 和 CSRF Token。

同一来源 IP 连续登录失败 5 次后，该 IP 的登录尝试阻断 15 分钟。此限制避免远程攻击者通过反复尝试锁死全局管理员账号。成功登录后清理对应失败计数。

会话 12 小时无活动后过期，且从创建起最多保留 7 天。主动退出立即删除服务端会话并清除 Cookie。过期会话由定期清理任务删除。

## 10. 会话过期恢复

管理员页面收到会话失效响应时不跳转离开当前页面，而是暂停所有修改操作并显示重新登录对话框。

- 当前照片、滚动位置、筛选状态和未保存文字草稿保留在当前标签页内。
- 草稿不写入 `localStorage` 或其他长期浏览器存储。
- 登录成功后关闭对话框并刷新 CSRF 材料。
- 未保存草稿不会自动提交；管理员重新点击保存。
- 已上传成功的照片保持已发布。
- 正在上传和等待上传的照片进入暂停状态。
- 管理员点击“继续上传”后恢复队列；客户端请求 ID 防止重复生成照片。
- 如果刷新或关闭标签页，浏览器无法保留尚未上传的本地文件，管理员需要重新选择。

## 11. 上传约束

- 一次文件选择最多 10 张。
- 单张请求最多 10MB。
- 支持 HEIC、HEIF、JPEG、PNG 和 WebP。
- 单张图片最多 6000 万像素。
- 浏览器最多同时上传 2 张。
- API 最多同时处理 1 张，额外任务有界排队。
- 服务器可用磁盘空间低于 5GB 时拒绝新上传并返回存储空间不足。
- 前端预检用于快速反馈，服务端必须独立重复全部校验。

服务端根据文件签名和解码结果判断真实格式，不信任扩展名、浏览器 MIME 或原文件名。超出选择数量、请求大小、像素限制、格式限制、队列上限或磁盘阈值时，在写入正式目录和数据库前失败。

## 12. 单张图片处理流程

1. 为本次请求创建服务端上传请求 ID 或验证客户端幂等 ID。
2. 以随机临时文件名流式写入 `staging`，同时执行请求大小上限。
3. 校验真实格式并读取尺寸、方向和可用的拍摄日期。
4. 拒绝超过 6000 万像素或无法安全解码的文件。
5. 自动纠正 EXIF 方向。
6. 不携带输入元数据地生成净化主图，因此 GPS、设备信息和其他 EXIF 不进入正式文件。
7. 生成最大宽度 320、640、960 和 1600 的响应式输出；不放大小于目标宽度的原图。
8. 为浏览器生成 AVIF、WebP 和 JPEG 可用资源，并记录实际存在的宽度。
9. 将完整照片目录原子移动到 `media/<photo-id>`。
10. 在 SQLite 事务中写入照片和媒体清单；正常上传在上传开关已开启时标记为已发布。
11. 返回公开照片数据，前端立即把照片加入照片库。

任何步骤失败都必须清理本次 staging 和未发布正式目录，不创建可见照片记录。一次批量操作中的其他照片继续处理，后台逐张显示结果并支持失败项重试。

默认标题使用“`YYYY年M月D日的成长瞬间`”，不公开原文件名。拍摄日期优先取可信照片元数据中的日历日期；缺失或非法时使用 Asia/Shanghai 时区下的上传日期。管理员之后可以修改标题、拍摄日期和可选图片描述；修改日期后公开相册自动重新排序。

## 13. 编辑和永久删除

编辑操作只修改标题、拍摄日期和图片描述，不重新处理媒体文件。并发修改使用更新时间或版本号检测，旧页面不能静默覆盖较新的数据。

删除前显示照片预览和明确的二次确认。确认后执行永久删除，不提供回收站。

删除实现先把正式媒体目录原子移动到不可公开访问的临时删除区，再在事务中删除数据库记录。数据库事务失败时恢复目录；事务成功后清理临时删除目录。清理失败只产生不可公开的待清理文件，由维护任务重试，不恢复已经确认删除的公开记录。

## 14. 管理员界面

采用照片库优先的布局：

- 未登录时显示简洁的用户名和密码登录页。
- 登录后直接显示照片网格和紧凑工具栏。
- 工具栏提供上传、刷新和退出登录。
- 桌面端点击照片后在右侧编辑标题、拍摄日期和图片描述。
- 手机端使用双列照片网格，编辑时进入全屏编辑视图。
- 上传按钮在手机上位于易于单手触达的位置，并调用系统照片选择器。
- 上传队列逐张显示缩略图、状态、进度、失败原因、重试和继续操作。
- 删除使用图标按钮和明确的二次确认对话框。

首次迁移准备阶段显示醒目的“正在准备旧照片，暂未开放上传”状态。此时上传按钮禁用，但管理员可以逐张填写五张旧照片的真实或大致拍摄日期，并修改标题和图片描述。

界面覆盖首次加载、空照片库、加载失败、网络中断、会话过期、上传暂停、部分失败和磁盘不足状态。交互元素有稳定尺寸、可见焦点、键盘支持、屏幕阅读器名称和必要的 `aria-live` 状态通知。

## 15. 公开相册改造

迁移准备阶段的公开相册继续从 `src/data/memories.ts` 读取静态照片，不受后台准备工作影响。激活发布后，公开相册改为从 `GET /api/photos` 获取照片，不再从静态数组读取照片数据。现有照片卡片、选择交互、响应式 `picture/srcset` 和成长日期顺序保持一致。

页面加载期间为照片墙预留稳定空间。接口失败时显示不遮挡其他内容的重试状态。现有视频、音频和睡眠视图仍使用静态构建资源，不纳入本期上传系统。

媒体 URL 使用不可预测照片 ID 和固定派生文件名。生成文件视为不可变资源，可使用长期缓存；编辑标题或日期不改变媒体 URL。

## 16. 现有五张照片迁移

仓库只保留现有照片的 320、640 和 960 像素派生文件，没有原始照片。一次性迁移脚本因此：

- 使用现有 960 像素 JPEG 作为净化主图。
- 复制现有 AVIF、WebP 和 JPEG 响应式资源到持久化媒体目录。
- 写入当前标题和详细图片描述。
- 以 `migration_pending` 状态导入，拍摄日期初始为空，不进入公开 API。
- 保留当前稳定旋转和偏移参数。
- 可重复执行而不创建重复照片。

导入后，管理员在 `/admin` 为每张照片手工填写真实或大致拍摄日期。准备检查必须确认五张照片均有合法日期、标题、公开描述和完整媒体资源，并能按出生、第一次开心微笑、满月、睡觉和公园的预期顺序排列。检查通过前不得激活 API 相册或开放上传。

迁移准备和管理员填写日期期间，公开页面仍使用原有静态照片数组。用户以后可以通过删除并重新上传的方式使用自己保留的原始照片，但这不是首期迁移要求。

## 17. 发布和回退

首次上线分为两个阶段。

### 17.1 准备阶段

1. 部署 API、管理界面、SQLite 和持久化目录，但公开相册继续使用静态照片数组。
2. 保持 `uploads_enabled=false`，上传接口拒绝新照片。
3. 幂等导入五张旧照片为 `migration_pending`。
4. 管理员登录并手工补齐五张旧照片的真实或大致拍摄日期。
5. 运行准备检查，验证记录、媒体资源、公开描述和排序；这个阶段不改变公开网站的数据来源。

### 17.2 激活阶段

1. 再次运行准备检查，任何旧照片未完成时立即停止。
2. 在事务中把五张旧照片标记为 `published`；该操作可重复执行。
3. 发布从 `GET /api/photos` 读取照片的新前端。
4. 检查 HTTPS 首页、公开照片接口、五张照片顺序和至少一张媒体资源。
5. 只有所有公网检查通过后，才设置 `uploads_enabled=true` 并验证上传接口已开放。

激活失败时回退前端，并确保 `uploads_enabled=false`。已经标记为 `published` 的旧记录不会影响仍读取静态数组的旧前端；再次激活时复用这些记录，不重复导入。这样即使切换中断，也不会在新旧公开数据源之间漏掉管理员刚上传的新照片。

### 17.3 后续 Tag 发布

首次激活完成后的 Tag 工作流扩展为：

1. 运行 lint、类型检查、单元测试、API 集成测试、部署测试和前后端构建。
2. 打包静态前端和 Linux 目标后端程序。
3. 上传后端到新的 `/opt/sweet-memories-api/releases/<commit-sha>`。
4. 对 SQLite 创建部署前本地快照，并执行向后兼容迁移。
5. 原子切换后端 `current`，重启 `systemd` 服务并检查 API。
6. API 健康后，使用现有发布管理器切换静态前端。
7. 检查 HTTPS 首页、公开照片接口和至少一张媒体资源；不得重置已启用的上传开关。
8. 成功后清理旧程序版本，绝不清理持久化数据目录。

API 检查失败时回退后端程序软链接并重启旧服务，前端不切换。前端或公网检查失败时使用有条件回退，避免覆盖并发发布的新版本。数据库迁移必须保持旧后端可读；破坏性迁移只能经过单独维护流程，不能进入自动 Tag 发布。

## 18. 备份和恢复

提供服务器备份命令，在持久化数据一致性锁内生成：

- SQLite 在线备份副本
- 媒体目录归档
- 数据库和媒体校验清单
- 带时间戳的压缩包和摘要

管理员必须把备份包下载到 Mac 或其他独立存储。同一系统盘上的备份只能防止误操作，不能防止云盘或服务器损坏。数据库迁移前的自动 SQLite 快照是短期回退保护，不替代异地备份。

恢复流程先校验归档和摘要，在独立临时目录解压，验证数据库及媒体引用一致性，再在维护状态下切换数据。恢复不得直接覆盖正在使用的数据目录。

原始照片由用户自行保留，服务器不承担原始文件永久归档职责。

## 19. 运行维护和监控

- `systemd` 在开机时启动 API，并在异常退出后有界重启。
- 日志写入 `journald`，禁止记录密码、Cookie、Token、CSRF、原文件名和照片内容。
- 定期维护清理过期会话、失败 staging、待删除目录和超期程序版本。
- 当前生产站点巡检增加 `/api/health`、`/api/photos` 以及一张同源媒体资源检查。
- Lighthouse 继续检查公开 HTTPS 页面，不访问管理员路由。
- 管理员上传和编辑错误在当前页面报告；本期不新增短信、微信或独立告警服务。

## 20. 错误处理原则

- 客户端错误不能产生正式文件或照片记录。
- 服务端错误逐张隔离，不能让整个批次失去已成功结果。
- 每个修改请求具备幂等边界，网络重试不能创建重复照片或重复删除。
- 认证失效统一暂停修改并进入会话恢复流程。
- SQLite 和文件系统跨边界操作使用事务、原子重命名和补偿清理保持可恢复一致性。
- 磁盘不足、队列繁忙和处理失败使用明确状态，不伪装为网络错误。
- 公共 API 降级不能泄露管理信息、堆栈、绝对路径或依赖版本。

- Tag 发布中的持久化隔离、API 切换、前端切换、健康检查和程序回退。

## 22. 实施分段

该功能由相互依赖但边界清晰的五段组成：
